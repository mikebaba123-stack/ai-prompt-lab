เปิด https://aistudio.google.com/apps → **Build** (หรือ "Create app") → วางพรอมป์ด้านล่าง → กด Run/Build

## 4.1 แอปที่อยากลองสร้าง

**ชื่อ:** **Prompt Coach — ผู้ช่วยตรวจและยกระดับพรอมป์**

**ปัญหาที่อยากแก้:** จากงานชิ้นก่อน (ฝึกเขียน Prompt 6 แง่) พบว่าพรอมป์แบบ zero-shot มักได้ผลลัพธ์กว้างและคาดเดาไม่ได้
แต่เวลาจะแก้ให้เป็น few-shot คนส่วนใหญ่ไม่รู้ว่า "ขาดอะไร" ถึงต้องลองผิดลองถูกหลายรอบ

**แอปนี้ทำอะไร:** ผู้ใช้วางพรอมป์ของตัวเองลงไป แอปจะ
1. ให้คะแนน 5 ด้าน (บริบท · ความเจาะจง · รูปแบบผลลัพธ์ · ตัวอย่าง/ข้อจำกัด · เกณฑ์วัดความสำเร็จ) ด้านละ 0–5
2. บอกว่า **ขาดอะไร** เป็นข้อ ๆ พร้อมเหตุผล
3. เขียน **พรอมป์ฉบับปรับปรุง** ให้เลย พร้อมช่องให้เติมบริบทที่แอปยังไม่รู้
4. แนะนำ **negative prompt** (สิ่งที่ไม่ต้องการ) ที่เหมาะกับงานประเภทนั้น

**ทำไมถึงเลือกแอปนี้:** เป็นการเอาบทเรียนจากงานชิ้นก่อน (หลักการ 5 ข้อของพรอมป์ที่ดี) มาทำเป็นเครื่องมือที่ใช้ซ้ำได้จริง
ไม่ใช่แค่ demo ลอย ๆ

## 4.2 พรอมป์ที่ใช้สร้างแอป (คัดลอกทั้งบล็อกไปวางใน AI Studio)

```text
สร้างเว็บแอปหน้าเดียวชื่อ "Prompt Coach" สำหรับช่วยปรับปรุงพรอมป์ภาษาไทย

หน้าตาแอป:
- ช่องข้อความใหญ่ให้ผู้ใช้วางพรอมป์ของตัวเอง
- เมนูเลือกประเภทงาน: ข้อความ / รูปภาพ / โค้ด / สไลด์ / ไดอะแกรม
- ปุ่ม "ตรวจพรอมป์"

เมื่อกดปุ่ม ให้แสดงผล 4 ส่วนตามลำดับ:
1. ตารางคะแนน 5 ด้าน ด้านละ 0-5 พร้อมคะแนนรวม
   - บริบท (ใครใช้ ใช้ทำอะไร)
   - ความเจาะจง (ประธาน ตัวแปร สไตล์)
   - รูปแบบผลลัพธ์ (ความยาว โครงสร้าง ไฟล์)
   - ตัวอย่างและข้อจำกัด
   - เกณฑ์วัดว่าผลลัพธ์ใช้ได้
2. รายการ "สิ่งที่ขาด" เป็น bullet พร้อมเหตุผลสั้น ๆ ต่อข้อ
3. พรอมป์ฉบับปรับปรุงในกล่องโค้ดที่กดคัดลอกได้
   ถ้าจุดไหนต้องให้ผู้ใช้เติมเอง ให้ใส่เป็น [ระบุ: ...]
4. negative prompt ที่แนะนำสำหรับประเภทงานที่เลือก

ข้อกำหนด:
- ใช้ภาษาไทยทั้งหมด
- โทนสีฟ้าอ่อน-กรมท่า สะอาดตา ใช้การ์ดมุมมน
- ทำงานบนมือถือได้
- ถ้าผู้ใช้วางพรอมป์ว่าง ให้เตือนอย่างสุภาพ ไม่ต้องเรียก API
```

## 4.3 สิ่งที่ต้อง capture ส่งอาจารย์

1. หน้าจอ AI Studio ตอนวางพรอมป์ลงไป (เห็นข้อความพรอมป์)
2. หน้าจอแอปที่สร้างเสร็จแล้ว
3. หน้าจอตอนทดลองใช้จริง — แนะนำให้วางพรอมป์ zero-shot จากงานชิ้นก่อน เช่น `สร้างรูปเกี่ยวกับปัญญาประดิษฐ์`
   แล้วถ่ายผลลัพธ์ที่แอปให้คะแนนและเขียนพรอมป์ใหม่ให้

## 4.4 อธิบายการทำงานของแอป (เติมหลังเห็นผลจริง)

**การทำงานตามที่ออกแบบ:** ผู้ใช้ป้อนพรอมป์ + เลือกประเภทงาน → แอปส่งข้อความนั้นเข้าโมเดล Gemini
พร้อมคำสั่งระบบที่กำหนดเกณฑ์ 5 ด้าน → โมเดลคืนผลเป็นโครงสร้าง 4 ส่วน → หน้าเว็บนำมาแสดงเป็นตารางและกล่องโค้ด

**สิ่งที่ควรสังเกตและจดไว้ตอนทดลอง**

| หัวข้อ | สิ่งที่ต้องดู | ผลที่ได้จริง (เติมเอง) |
|---|---|---|
| สร้างเสร็จในรอบเดียวไหม | ต้องสั่งแก้กี่รอบถึงได้หน้าตาที่ต้องการ | |
| ทำตามข้อกำหนดครบไหม | ครบทั้ง 4 ส่วนหรือไม่ · ภาษาไทยล้วนหรือไม่ · มือถือใช้ได้ไหม | |
| คุณภาพการให้คะแนน | คะแนนสมเหตุสมผลไหม เมื่อลองพรอมป์ดีกับพรอมป์แย่ ผลต่างกันชัดไหม | |
| พรอมป์ฉบับปรับปรุง | นำไปใช้ได้จริงไหม หรือยังกว้างเหมือนเดิม | |
| ข้อจำกัดที่เจอ | เช่น แก้ดีไซน์ยาก · ผลไม่คงที่เมื่อกดซ้ำ · โควตาการใช้งาน | |

**หัวข้อสำหรับเขียนวิจารณ์ความพอใจ**
- **สิ่งที่ทำได้ดี:** สร้าง UI ที่ใช้ได้จากคำอธิบายภาษาไทยล้วน ไม่ต้องเขียนโค้ดเอง ประหยัดเวลาตั้งต้นมาก
- **สิ่งที่ยังไม่พอใจ:** (ดูจากผลจริง เช่น การจัดวางไม่ตรงที่สั่ง / คะแนนที่ให้ไม่คงที่ / แก้รายละเอียดเล็ก ๆ ยากกว่าลงมือเขียนเอง)
- **สรุป:** เหมาะกับการทำต้นแบบเร็ว ๆ เพื่อดูว่าไอเดียเวิร์กไหม แต่ถ้าจะใช้งานจริงยังต้องมีคนแก้ต่อ
